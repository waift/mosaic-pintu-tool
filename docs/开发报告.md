## 一、项目速览

| 项 | 内容 |
|---|---|
| **定位** | 纯前端、浏览器本地的长图 / 拼图拼接工具 |
| **隐私模型** | 图片**全程不出浏览器**，无后端、无上传，全部在本地 Canvas 处理 |
| **仓库** | https://github.com/waift/mosaic-pintu-tool （public） |
| **线上** | https://waift.github.io/mosaic-pintu-tool/ |
| **包名 / 版本** | `mosaic-tool` / `0.0.0`（尚未启用语义化版本，见技术债 D9） |
| **源码规模** | 22 个文件，约 2,938 行（含 381 行测试） |
| **产物形态** | **双产物**：① 在线网站（`dist/`，CI 自动部署）② 离线单文件（`拼图工具.html`，约 399KB，双击即用） |

### 双产物是理解本项目的第一把钥匙

很多设计上的"怪异之处"都源于此。单文件版通过 `file://` 协议运行，这带来三条硬约束：

1. **不能用 BrowserRouter**（无服务器路由）→ 全局统一 HashRouter，见 ADR-1
2. **不能有外部资源引用** → 所有 JS/CSS/字体必须内联进单个 HTML
3. **不能联网调用 API** → 任何依赖远程服务的功能都会在离线版失效（这一条限制了未来的 AI 类功能）

## 二、技术栈与架构

技术栈清单见 [README](../README.md#技术栈)，此处只记**选型理由与架构关系**。

### 分层结构

```
main.tsx  ──> ErrorBoundary ──> App(HashRouter) ──> pages/Home.tsx
                                                        │
                    ┌───────────────────────────────────┼───────────────────────┐
                    ▼                                   ▼                       ▼
              UploadZone                          ImageList /            StitchConfig
              (上传入口)                       ImageManagerModal          (拼接参数)
                    │                            (排序 / 批量管理)              │
                    └──────────────┬─────────────────────┘                     │
                                   ▼                                           ▼
                        store/stitchStore.ts  ◄──────────────────────────────────
                        (zustand 单体 store：images / config / status / result / toast)
                                   │
                                   ▼
                        utils/image.ts（纯计算层，无 React 依赖）
                        decode → EXIF 校正 → planStitch 布局 → Canvas 绘制 → Blob 导出
```

### 关键设计

**`utils/image.ts` 是本项目的计算内核**（360 行，11 个导出）。它刻意**不依赖 React、不依赖 store**，所有函数接收参数返回结果。这带来两个好处：

- 可以脱离浏览器 UI 直接单元测试（48 条测试全打在这一层）
- 拼接逻辑的正确性与 UI 改动解耦——改拖拽不会影响导出尺寸

主要函数职责：

| 函数 | 职责 | 易碎点 |
|---|---|---|
| `applyOrientationSize` | EXIF 方向 → 宽高是否互换 | 边界 `>=5 && <=8`，改错一端就悄悄坏 |
| `decodeImage` | File → ImageBitmap + 方向信息 | 异步，依赖 exifr |
| `validateFiles` | 类型过滤 + 30 张上限 | 数量边界 |
| `filterBySize` | 8000px 最长边校验 | **超限必须 `close()` 位图**，否则内存泄漏 |
| `bitmapToOrientedCanvas` | 按 8 种 orientation 做 rotate/scale 校正 | transform 顺序、save/restore 配对 |
| `planStitch` | 等比缩放 + 间距累加 + 坐标计算 | 间距是 `gap × (n-1)`；16000px Canvas 上限保护 |
| `stitchAndExport` | 执行绘制并导出 Blob | 格式/质量参数 |
| `hexToRgba` | 颜色解析（`#rgb` / `#rrggbb` / `#rrggbbaa`） | 缩写展开 |

**状态管理**：`stitchStore.ts` 是**单体 store**（113 行），当前规模下清晰够用，但已被列为技术债 D4——一旦接入撤销重做或单图编辑，需要拆 slice。

## 四、关键架构决策记录（ADR）

> 这一节是文档里**最值钱的部分**。每条都记录了「当时为什么这么选」，避免后来者（包括未来的你）推翻决策后重新踩一遍坑。

### ADR-1：全局统一 HashRouter，不做运行时路由切换

- **决策**（`3a001dd`）：`App.tsx` 始终使用 `HashRouter`。
- **背景**：早期版本（`bd06e50`）曾按 `window.location.protocol` 运行时选择路由——`file:` 用 Hash，`http(s):` 用 Browser。
- **为什么推翻**：GitHub Pages 把站点挂在**子路径** `/mosaic-pintu-tool/` 下，BrowserRouter 的根路径不匹配，线上直接白屏。
- **代价**：URL 带 `#`，略不美观。可接受——本项目只有 `/` 一个路由。
- ⚠️ **不要改回去**。README「不要动的两处」之一。

### ADR-2：`base: './'` 相对路径

- **决策**（`55ecc66`）：`vite.config.ts` 设 `base: './'`。
- **原因**：同时满足两个部署场景——GitHub Pages 子路径、单文件 `file://` 协议。绝对路径 `/assets/...` 在两者下都会 404。
- ⚠️ **不要改**。README「不要动的两处」之二。

### ADR-3：拖到队列末尾用「指针坐标判定」，而非 droppable 哨兵

- **决策**（`020fb44`）：在 `onDragEnd` 里用 `activatorEvent.clientY + delta.y` 算出指针最终 Y，与末尾投放区 DOM 的 `getBoundingClientRect().top` 比较，`pointerY >= top - 6` 即视为投放到末尾。
- **为什么不用常规方案**：原本用 `useDroppable({ id: "__DROP_END__" })` 建哨兵投放区，但 Playwright 实测打印 `droppableContainers` 发现——**该哨兵从未注册成功**（`endRect === undefined`），`pointerWithin` 永远只返回图片 id，`over` 从不等于 `__DROP_END__`。
- **教训**：dnd-kit 的 droppable 注册在某些布局下会静默失败，不报错。**遇到"碰撞检测不命中"，先打印 `droppableContainers` 确认目标是否真的在列表里**，别急着调碰撞算法。

### ADR-4：多选拖动时原地保留「虚线占位镜像」

- **决策**（`020fb44`）：整组拖动时，所有选中项（**含正在被拖的那张**）原地显示 `border-2 border-dashed border-accent-400/70 + opacity-40`。
- **被否决的替代方案**：方案 C（收缩成 12px 细槽）与方案 B（完全抽走 + FLIP 动画）。详见 [功能规划 · 已否决方案](./功能规划.md#附已否决方案)。
- **要点**：不是"没做更炫的"，是**用户实测后明确否决**。不要重新提案。

### ADR-5：单击上传区不读剪贴板

- **决策**（`620afd2`）：单击只切换 `armed` 高亮态并提示"按 Ctrl+V 粘贴图片"，**不调用** `navigator.clipboard.read()`。
- **原因**：自动读剪贴板会触发浏览器权限弹窗、剪贴板为空时弹无意义 toast，体验割裂。
- **配套约定**：全局 `Ctrl+V`（`Home.tsx` 监听）**始终可用**，单击仅作视觉引导；高亮在「粘贴成功 / 点击别处 / Esc」三者任一时解除。

### ADR-6：测试用 jsdom 打桩，不引入 node-canvas

- **决策**（`8482e94`）：`src/test/setup.ts` 手写 Canvas 2D 上下文桩，用 WeakMap 记录 `rotate/scale/translate` 调用序列供断言。
- **原因**：jsdom 未实现 `getContext()`，返回 `null` 会让 `bitmapToOrientedCanvas` 崩在 `ctx.save()`。而引入 node-canvas 需要原生编译、拖慢 CI。
- **判断依据**：我们要验证的是**布局计算是否正确**，不是像素输出是否好看。打桩足够，且能断言"orientation 6 是否真的转了 90°"。

### ADR-7：Vitest 关闭 globals

- **决策**：`vitest.config.ts` 设 `globals: false`，测试文件显式 `import { describe, it, expect } from "vitest"`。
- **原因**：避免污染全局类型，tsc 与 eslint 无需额外配置即可正确识别测试文件。

## 五、踩坑清单（Bug 档案）

> 这些坑都真实发生过、耗费过排查时间。重复踩不值得。

### 坑 1：`single.html` 绝对不能删 ⚠️

根目录的 `single.html` **不是构建残留副本**，它是 `vite.singlefile.config.ts` 第 21 行指定的**构建入口模板**：

```ts
input: fileURLToPath(new URL("single.html", import.meta.url)),
```

内含防主题闪烁的内联脚本。删掉它 `npm run build:single` 直接失败，离线版打不出来。

### 坑 2：`拼图工具.html` 被 gitignore，提交需 `-f`

`.gitignore` 里忽略了 `拼图工具.html`（早期为防误提交）。但它现在是**要交付的产物**，必须提交。用：

```bash
git add -f "拼图工具.html"
```

### 坑 3：`useEffect` 依赖数组含被清理的 state → 状态自我重置

弹窗"查看大图"点了没反应，排查很久。根因：清理用的 `useEffect` 依赖数组里含 `previewId`，导致每次 `previewId` 变化都先跑 cleanup 里的 `setPreviewId(null)`——**刚设的值被立刻重置**。

修法：用 `useRef` 跟踪值，清理 effect 依赖数组置空（仅挂载/卸载时执行）。

### 坑 4：`opacity-0` 的悬浮按钮仍可点击，会抢走点击事件

"多选后无法整组拖动"的真凶：眼睛按钮用 `group-hover` 浮现在缩略图**正中心**，`z-20` 最高，且 `opacity-0` 状态下**依然响应点击**。用户点缩略图想选中，实际命中了眼睛 → 选中集永远为空 → 整组拖动分支不触发。

修法：眼睛移到右下角（`right-0 bottom-0`），把中心区域让给选中/拖拽。
**通用教训**：`opacity-0` ≠ 不可点击，需要 `pointer-events-none` 才是。

### 坑 5：GitHub Pages 免费 runner 会排队卡住

`f56138b` 那次，build 成功但 deploy 步骤在队列里卡死。解法：推一个空提交触发新 run，新 run 会取消旧的排队任务。

```bash
git commit --allow-empty -m "chore: 重新触发部署"
```

### 坑 6：Vite build 不做完整类型检查

`vite build` 只转译不校验类型，类型错误照样能打包上线。这正是 CI 要单独跑 `tsc -b --noEmit` 的原因（虽然 `npm run build` 脚本本身已含 `tsc -b`，CI 里单独前置一步能更早失败、报错更清晰）。

### 坑 7：GitHub API 未认证会被限流

查 Actions 状态时 `curl` GitHub API 返回 403（未认证限流），本机也没装 `gh` CLI。替代验证方案：**抓线上产物 JS 直接 grep 特征字符串**，比查 CI 状态更直接地证明"改动到底上没上线"。

```bash
curl -s https://waift.github.io/mosaic-pintu-tool/ | grep -o 'assets/index-[A-Za-z0-9_-]*\.js'
curl -s "https://waift.github.io/mosaic-pintu-tool/assets/index-XXXX.js" | grep -c "特征文案"
```

## 六、质量保障体系

### 三道 CI 门禁

`.github/workflows/deploy.yml` 在 Build 之前依次执行，**任一失败则不部署**（GitHub Actions 中命令返回非零退出码会立即中断整个 job）：

```
tsc -b --noEmit  →  eslint .  →  vitest run  →  build  →  deploy Pages
```

本地 push 前自查（与 CI 完全等价）：

```bash
npm run check && npm run lint && npm test
```

### 测试覆盖现状

48 条用例，全部集中在 `utils/image.ts`，跑一次约 0.8 秒。

| 被测函数 | 用例数 | 覆盖重点 |
|---|---:|---|
| `applyOrientationSize` | 12 | EXIF 8 种方向 + **正反卡住 `>=5 && <=8` 两端边界** |
| `planStitch` | 11 | 垂直/水平等比放大、间距只加在图片间、坐标递增、16000px 上限 |
| `filterBySize` | 6 | 8000px 边界、**超限时位图必须 close** |
| `validateFiles` | 6 | 非图片过滤、30 张上限截断 |
| `hexToRgba` | 6 | `#abc` 缩写展开、8 位 alpha |
| `bitmapToOrientedCanvas` | 6 | 旋转角度、镜像 scale、save/restore 配对 |
| `uid` | 2 | 1000 次不重复 |

**未覆盖**：组件层、store 层、`decodeImage` / `stitchAndExport`（依赖真实浏览器 API）。见技术债 D2。

### 变异测试：验证测试本身有效

"全绿"不等于"测试有用"。引入测试时做过一次验证——故意往源码注入 bug，确认测试会变红：

| 注入的 bug | 被抓住的测试数 |
|---|---:|
| `applyOrientationSize` 的 `>= 5` 改成 `> 5` | 2 |
| `planStitch` 的 `gap * (n - 1)` 改成 `(n - 2)` | 4 |

并验证退出码：通过 `0` / 失败 `1`，确认 CI 能真正拦截。

**这套流程可复用**：`cp src/x.ts /tmp/x.backup.ts` → 脚本注入变异 → 跑测试看红 → `cp` 恢复 → `git diff --stat` 确认干净。

### 浏览器端验证

本项目大量交互问题（拖拽、点击穿透）**无法靠单元测试发现**，历史上是用 Playwright + 系统 Chrome（`channel: 'chrome'`）驱动 dev server 实测定位的。若需复现：

- dev server：`npm run dev -- --host 127.0.0.1`
- Playwright 装在 `/Users/wubingyong/.workbuddy/binaries/node/workspace`

## 九、维护者速查

### 常用命令

```bash
npm run dev            # 本地开发
npm run check          # 类型检查
npm run lint           # 代码规范
npm test               # 单元测试（48 条，约 0.8s）
npm run test:watch     # 测试监听模式

npm run build          # 产出 dist/（推送后 CI 会自动做）
npm run build:single   # 产出 dist-single/single.html
cp dist-single/single.html "拼图工具.html"   # 更新离线版
```

### 提交前必做

```bash
npm run check && npm run lint && npm test
```

### 高危操作清单 ⚠️

| 操作 | 后果 |
|---|---|
| 改 `App.tsx` 的 HashRouter | 线上白屏（ADR-1） |
| 改 `vite.config.ts` 的 `base: './'` | 线上资源 404（ADR-2） |
| 删根目录 `single.html` | 离线版构建失败（坑 1） |
| 半成品直接 push `main` | **main = 生产环境，push 即上线** |
| 改源码但忘记重建 `拼图工具.html` | 离线版与网站版脱节（曾发生，落后过 2 个版本） |
| 加/删依赖后不提交 `package-lock.json` | CI 用 `npm ci`，线上与本地不一致 |

### 改完源码后别忘了

网站版由 CI 自动构建部署，但**离线单文件必须手动重建**：

```bash
npm run build:single && cp dist-single/single.html "拼图工具.html"
git add -f "拼图工具.html"
```
